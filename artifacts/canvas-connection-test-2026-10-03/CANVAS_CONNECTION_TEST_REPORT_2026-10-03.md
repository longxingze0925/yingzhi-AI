## 执行环境与阻断证据

- `http://localhost:3002/studio/canvas` HTTP 200，但客户端随后跳转到 `http://localhost:3002/login?next=%2Fstudio%2Fcanvas`。
- 浏览器实际发出的同源请求：
  - `GET http://localhost:3002/api/status` → **404 HTML**
  - `GET http://localhost:3002/api/studio/bootstrap` → **404 HTML**
- 独立 API 服务 `http://localhost:3000`：
  - `GET /api/status` → **200 JSON**
  - `GET /api/studio/bootstrap` → **401 AUTH_UNAUTHORIZED**（没有有效登录凭证）
- 当前前端客户端 `lib/api/client.ts` 默认 API base 为 `/api`，因此本地浏览器请求落在 3002 同源；当前 3002 Next 开发服务没有对应 API 路由。真实 API 的 bootstrap 又需要登录 token。

**阻断结论：**需要修正本地前端到真实 API 的代理/`NEXT_PUBLIC_API_BASE_URL` 配置，并提供有效测试账号登录后，才能执行连接测试。为了遵守“不使用模拟数据”的要求，本轮没有伪造 token、没有将请求转发到假服务、没有尝试创建账号或改动正在运行的服务。

## 源码静态审查（不是 UI 测试结论）

1. **连接点可能被调整手柄覆盖（P1 风险）**：连接点和左右中点 resize handle 同坐标；resize handle `z-20` 高于连接点 `z-10`。两者仅在选中节点时同时出现。需先修复或在真实浏览器验证命中目标，否则连接创建可能不可操作。
2. **方向曲线控制点固定（P1 风险）**：贝塞尔路径控制点始终假设起点向右、终点向左，没有考虑连接侧；左侧起点/右侧终点可能出现反向或不自然曲线。
3. **导入导出明确遗漏连线（P1）**：导出 JSON 不包含 `connections`；导入解析数据类型和项目更新也不恢复 `connections`。这是源码确认的问题，但本轮未通过真实 UI 下载文件复现。
4. **节点菜单删除可能留下孤立连线数据（P2）**：批量删除函数会过滤相关连线，但单节点 `deleteNode` 不处理 connections；菜单删除走单节点路径。孤立线因端点缺失可能不渲染，却仍可能留在项目数据。
5. **首次连线无草稿预览（P2）**：状态中记录起点，但未找到草稿 SVG 渲染。
6. **快捷键焦点需验证（P2）**：Escape 处理跳过 `button`/`select` 焦点；连接点是 button，实际按下 Escape 是否能清理连接草稿需实测。
7. Store 使用 Zustand `persist`，项目中包含 `connections` 字段，理论上可随项目本地持久化；仍需真实刷新确认。

详细机器可读审查记录见 `source_audit.json`。

## 发现的问题

### P0 - 当前验收阻断

- **问题：**当前 3002 前端同源 `/api/*` 返回 Next 404，页面跳转登录；3000 API 状态接口可用，但 bootstrap 未认证时返回 401。
- **重现：**无 token 的 Playwright Chromium 打开 `/studio/canvas`；浏览器记录两个 404 请求并最终落在登录页。
- **影响：**无法执行任何画布连接 UI 用例。
- **处理建议：**本地启动时让影织前端 API base/同源代理指向运行中的 New API，并使用有效测试账号登录。不要仅用 token 伪造绕过认证。
- **证据：**`screenshots/01_login_blocker.png`、`screenshots/02_frontend_api_status_404.png`、`screenshots/03_backend_bootstrap_401.png`、`api_checks.json`。

### P1 - 源码静态审查风险

- 连接点与边中 resize 手柄位置/层级重叠，可能导致连接点不可点击。
- 导入导出缺失 connections 字段，连线往返无法保存。
- 贝塞尔控制点未按 sourceSide/targetSide 决定方向。

### P2 - 源码静态审查风险

- 菜单删除单节点时可能残留相关连接数据。
- 连线草稿没有可见预览。
- 空白点击取消连线选中状态的行为未发现明确处理；需真实测试。

## 总结

**整体评价：**⚠️ 阻断，尚未完成连线功能真实浏览器验收。  
**真实 UI 通过率：**0/22 已验证；22/22 阻断（不是 22 项功能失败）。  
**源码审查结论：**存在至少 3 项需要优先处理/真实复核的问题，尤其连接点命中层级和导入导出丢连线。

建议下一步：
1. 修正本地 3002 → 真实 API 3000 的 API base/代理配置，提供有效测试账号登录。
2. 先处理连接点和 resize handle 的重叠层级，再执行 1.2/1.3 验证。
3. 将 connections 纳入 JSON 导出、校验和导入，之后执行 3.2 往返测试。
4. 登录后的真实浏览器重跑全部 22 组用例，再给出实际性能数据。
